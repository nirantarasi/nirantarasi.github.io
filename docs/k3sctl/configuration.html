Configuration ​

A k3sctl configuration is a single Cluster document with apiVersion: k3sctl.k3sproject.io/v1beta1.

yaml
apiVersion: k3sctl.k3sproject.io/v1beta1
kind: Cluster
metadata:
  name: demo
spec:
  hosts:
    - role: server
      ssh:
        address: 10.0.0.1
        user: root
        port: 22
        keyPath: ~/.ssh/id_ed25519
      privateAddress: 10.0.0.1        # advertises this IP to the cluster
      installFlags:
        - --disable=traefik
      labels:
        node-role.example.com/edge: "true"
      taints:
        - dedicated=edge:NoSchedule
      environment:
        ETCD_UNSUPPORTED_ARCH: arm     # rendered into the systemd unit
      files:
        - src: ./configs/registries.yaml
          dst: /etc/rancher/k3s/registries.yaml
          perm: "0600"
      hooks:
        apply:
          before:
            - echo preparing
          after:
            - echo done

    - role: agent
      ssh:
        address: 10.0.0.2
        user: root
        port: 22
        keyPath: ~/.ssh/id_ed25519

  k3s:
    version: v1.30.0+k3s1
    config:                            # merged into config.yaml on every host
      write-kubeconfig-mode: "0644"
      disable:
        - servicelb
    extraArgs:
      - --kubelet-arg=eviction-hard=memory.available<100Mi

    etcdSnapshots:                     # automated etcd snapshot scheduling
      scheduled: true
      scheduleCron: "0 */12 * * *"
      retention: 5
      dir: /var/lib/rancher/k3s/server/db/snapshots
      compress: true
      s3:
        enabled: true
        endpoint: s3.amazonaws.com
        bucket: my-k3s-backups
        region: us-east-1
        folder: snapshots
        accessKey: AKIAIOSFODNN7EXAMPLE
        secretKey: wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
      prune:                           # prune old snapshots on apply
        enabled: true
        retention: 10
        name: on-demand

    secretsEncrypt:                    # secrets encryption at rest
      enabled: true
      rotateKeys: true                 # dynamically rotate encryption keys
      reencrypt: true                  # re-encrypt all secrets with new keys

    certRotate:                        # certificate rotation on apply
      enabled: true
      rotateCA: true                   # rotate the root CA (full cluster restart)

    token:                             # cluster tokens
      serverToken: my-server-secret
      agentToken: my-agent-secret
      rotate: true                     # rotate token and restart all nodes

    registries:                        # private registry configuration
      mirrors:
        docker.io:
          endpoint:
            - https://registry.example.com
      configs:
        registry.example.com:
          auth:
            username: myuser
            password: mypass
          tls:
            caFile: /path/to/ca.pem
            insecureSkipVerify: false

    healthCheck:                       # post-apply health verification
      enabled: true
      timeout: 120s

    preflight:                         # pre-flight checks before apply
      enabled: true
      checkCgroups: true
      checkModules: true
      checkPorts: true
      checkDisk: true
      minDiskGB: 10

    airgap:                            # air-gap (offline) installation
      enabled: true
      imageBundle: /path/to/k3s-airgap-images-amd64.tar.zst

    network:                           # cluster networking
      clusterCIDR:
        - 10.42.0.0/16
      serviceCIDR:
        - 10.43.0.0/16
      clusterDNS:
        - 10.43.0.10
      clusterDomain: cluster.local
      nodePortRange: "30000-32767"
      flannelBackend: vxlan             # none, vxlan, host-gw, wireguard-native
      flannelIPv6Masq: false
      flannelExternalIP: false
      egressSelectorMode: agent         # agent, cluster, pod, disabled
      serviceLBNamespace: kube-system

    disable:                           # disable packaged components
      components:
        - traefik
        - servicelb
      scheduler: false
      cloudController: false
      kubeProxy: false
      networkPolicy: false
      helmController: false

    tls:                               # API server TLS SANs
      sans:
        - lb.example.com
        - 10.0.0.100
      sanSecurity: true

    kubeconfig:                        # kubeconfig output settings
      mode: "0644"
      group: admin
      name: my-cluster

    datastore:                         # external datastore (MySQL/Postgres/etcd)
      endpoint: "postgres://user:pass@db:5432/k3s"
      caFile: /etc/ssl/ca.pem
      certFile: /etc/ssl/cert.pem
      keyFile: /etc/ssl/key.pem

    server:                            # API server listener settings
      advertiseAddress: 10.0.0.50
      advertisePort: 6443
      bindAddress: 0.0.0.0
      httpsPort: 6443

    security:                          # security hardening
      selinux: true
      protectKernelDefaults: true
      encryptionProvider: secretbox     # aescbc or secretbox

    componentArgs:                     # typed pass-through args for K3s components
      kubeAPIServer:
        - "--audit-log-path=/var/log/audit.log"
      kubeControllerManager:
        - "--node-cidr-mask-size=24"
      kubeScheduler: []
      kubeCloudControllerManager: []
      kubelet:
        - "--max-pods=110"
      kubeProxy:
        - "--proxy-mode=ipvs"
      etcd:
        - "--quota-backend-bytes=8589934592"
      helmController: []

    runtime:                           # container runtime settings
      systemDefaultRegistry: registry.example.com
      pauseImage: registry.example.com/pause:3.9
      snapshotter: stargz
      defaultRuntime: nvidia

  options:
    drain:
      enabled: true
      timeout: 5m
      gracePeriod: -1
      ignoreDaemonSets: true
      deleteEmptyDirData: true
      disableEviction: false
    concurrency:
      limit: 30
      uploads: 5
    evictTaint:
      enabled: false

Hosts ​

spec.hosts is a list. Each entry describes one machine and the role it plays.

KeyDescription
roleserver (default) or agent
ssh / openSSH / localhostHow to reach the host
privateAddressAddress used for the node IP and API advertisements
privateInterfaceNetwork interface whose address is used for node IP and API advertisements
hostnameOverride the host name reported to the cluster
installFlagsExtra k3s server / k3s agent command-line flags
labels, taintsConvenience shortcuts for --node-label and --node-taint
environmentEnvironment variables written to the host and the systemd unit
filesFiles to upload, from a local path or a URL
hooksCommands to run before or after apply
dataDirOverrides the K3s data directory
uploadBinaryUpload a locally built binary instead of downloading one
k3sBinaryPathUse an existing binary already on the host
noFlannelDisable the flannel CNI
osOverride OS detection

SSH access ​

The ssh block takes an address, user, port, and keyPath. Use openSSH to reuse your OpenSSH client configuration, or localhost when the host is the machine running k3sctl.

Files and hooks ​

files entries copy a local path or download a URL to dst on the host. Use perm to set the mode. hooks.apply.before and hooks.apply.after run shell commands around the apply step, which is useful for pre-flight checks and post-install verification.

K3s ​

spec.k3s controls the K3s installation itself.

KeyDescription
versionK3s version to install, for example v1.30.0+k3s1
configMapping merged into config.yaml on every host
extraArgsExtra arguments passed to the K3s service
etcdSnapshotsAutomated etcd snapshot scheduling, S3 upload, and pruning
secretsEncryptSecrets encryption at rest with key rotation and re-encryption
certRotateRotate TLS certificates and optionally the root CA
tokenExplicit server/agent join tokens and optional rotation
registriesPrivate registry mirrors and authentication
healthCheckPost-apply cluster health verification
preflightPre-flight checks run before apply
airgapAir-gap (offline) installation settings
networkCluster and service CIDRs, DNS, flannel backend, egress mode, NodePort range
disableDisable packaged components and individual K3s subsystems
tlsSubject Alternative Names for the API server certificate
kubeconfigWrite-kubeconfig mode, group, and name
datastoreExternal datastore endpoint (MySQL/Postgres/etcd) with TLS
serverAPI server advertise address/port, bind address, HTTPS port
securitySELinux, protect-kernel-defaults, encryption provider
componentArgsTyped pass-through args for kube-apiserver, kubelet, etcd, and others
runtimeSystem default registry, pause image, snapshotter, default runtime

Binary sources can also be a URL, a local file, or an existing installation on the host; see the host-level uploadBinary and k3sBinaryPath options above.

etcdSnapshots ​

KeyDescription
scheduledEnable scheduled snapshots
scheduleCronCron expression for the snapshot schedule
retentionNumber of snapshots to retain
dirLocal directory for snapshots
compressCompress snapshots
s3.enabledStore snapshots in S3
s3.endpointS3 endpoint
s3.endpointCaPath to a CA certificate for the S3 endpoint
s3.skipSslVerifySkip TLS verification for S3
s3.accessKeyS3 access key
s3.secretKeyS3 secret key
s3.bucketS3 bucket name (required when S3 is enabled)
s3.regionS3 region
s3.folderFolder within the bucket
s3.insecureUse HTTP instead of HTTPS

etcdSnapshots.prune ​

KeyDescription
enabledEnable pruning of old etcd snapshots on apply
retentionNumber of snapshots to retain (required when enabled, must be greater than 0)
nameSnapshot name filter for pruning, for example on-demand

secretsEncrypt ​

KeyDescription
enabledEnable K3s secrets encryption at rest
rotateKeysDynamically rotate encryption keys
reencryptRe-encrypt all secrets with the new keys

certRotate ​

KeyDescription
enabledRotate K3s TLS certificates on each server during apply
rotateCARotate the root Certificate Authority; triggers a full cluster restart

token ​

KeyDescription
serverTokenToken used for server-to-server communication
agentTokenToken used for agent-to-server communication
rotateRotate the cluster join token and restart all nodes

registries ​

KeyDescription
mirrors.<registry>.endpointList of mirror endpoint URLs for the given registry
configs.<registry>.auth.usernameRegistry authentication username
configs.<registry>.auth.passwordRegistry authentication password
configs.<registry>.auth.tokenRegistry authentication token
configs.<registry>.tls.certFilePath to a client TLS certificate
configs.<registry>.tls.keyFilePath to a client TLS key
configs.<registry>.tls.caFilePath to a CA certificate for the registry
configs.<registry>.tls.insecureSkipVerifySkip TLS verification for the registry

The registries configuration is written to /etc/rancher/k3s/registries.yaml on all nodes during apply.

healthCheck ​

KeyDescription
enabledEnable post-apply cluster health verification
timeoutMaximum wait time for health checks, for example 120s or 5m

When enabled, the health check verifies the API server responds to /healthz and all nodes reach Ready status before the apply completes.

preflight ​

KeyDescription
enabledEnable pre-flight checks
checkCgroupsVerify cgroup v1/v2 controllers are available
checkModulesVerify required kernel modules are loaded
checkPortsVerify required ports are not in use
checkDiskVerify minimum disk space is available
minDiskGBMinimum disk space in GB

airgap ​

KeyDescription
enabledEnable air-gap mode (skip downloading K3s images from the internet)
imageBundleLocal path to a K3s air-gap image bundle, for example k3s-airgap-images-amd64.tar.zst

When enabled, the bundle is uploaded to <dataDir>/agent/images/ on every host.

network ​

Declarative cluster networking configuration. All fields are server-only.

KeyDescription
clusterCIDRPod CIDR ranges, for example ["10.42.0.0/16"] or dual-stack ["10.42.0.0/16", "fd42::/48"]
serviceCIDRService CIDR ranges, for example ["10.43.0.0/16"]
clusterDNSCluster DNS service addresses, for example ["10.43.0.10"]
clusterDomainCluster domain, for example cluster.local
nodePortRangeNodePort service port range, for example "30000-32767"
flannelBackendFlannel backend: none, vxlan, host-gw, or wireguard-native
flannelIPv6MasqEnable IPv6 masquerading for flannel
flannelExternalIPUse node external IPs for flannel traffic
egressSelectorModeEgress selector mode: agent, cluster, pod, or disabled
serviceLBNamespaceNamespace for the built-in ServiceLB controller

disable ​

Disable packaged K3s components and subsystems. Server-only.

KeyDescription
componentsList of packaged components to disable, for example ["traefik", "servicelb", "metrics-server", "coredns"]
schedulerDisable the kube-scheduler
cloudControllerDisable the cloud controller manager
kubeProxyDisable kube-proxy
networkPolicyDisable the network policy controller
helmControllerDisable the Helm controller

tls ​

TLS Subject Alternative Names for the API server certificate. Server-only.

KeyDescription
sansAdditional SANs for the API server TLS certificate, for example ["lb.example.com", "10.0.0.100"]
sanSecurityEnable TLS SAN security mode

kubeconfig ​

Controls how the admin kubeconfig file is written on server nodes. Server-only.

KeyDescription
modeFile permission mode for kubeconfig, for example "0644"
groupGroup ownership for the kubeconfig file
nameCluster name written into the kubeconfig

datastore ​

External datastore configuration for MySQL, PostgreSQL, or etcd. Server-only. TLS fields require endpoint to be set.

KeyDescription
endpointDatastore connection string, for example "postgres://user:pass@db:5432/k3s"
caFilePath to the CA certificate for the datastore TLS connection
certFilePath to the client certificate for the datastore TLS connection
keyFilePath to the client key for the datastore TLS connection

server ​

API server listener settings. Server-only.

KeyDescription
advertiseAddressAddress the API server advertises to cluster members
advertisePortPort the API server advertises (default 6443)
bindAddressAddress the API server binds to, for example "0.0.0.0"
httpsPortHTTPS listen port for the API server

security ​

Security hardening options. Applied to both server and agent nodes.

KeyDescription
selinuxEnable SELinux support in K3s
protectKernelDefaultsProtect kernel defaults; K3s will error if required kernel parameters are not set
encryptionProviderSecrets encryption provider: aescbc or secretbox

componentArgs ​

Typed pass-through arguments for Kubernetes components. Server-only args are applied only to server configs; kubelet and kubeProxy are applied to both server and agent configs.

KeyApplies toDescription
kubeAPIServerServerExtra arguments for kube-apiserver
kubeControllerManagerServerExtra arguments for kube-controller-manager
kubeSchedulerServerExtra arguments for kube-scheduler
kubeCloudControllerManagerServerExtra arguments for kube-cloud-controller-manager
kubeletServer + AgentExtra arguments for kubelet
kubeProxyServer + AgentExtra arguments for kube-proxy
etcdServerExtra arguments for etcd
helmControllerServerExtra arguments for the Helm controller

runtime ​

Container runtime settings. Applied to both server and agent nodes.

KeyDescription
systemDefaultRegistryDefault registry for all system images, for example "registry.example.com"
pauseImageOverride the pause container image
snapshotterContainerd snapshotter, for example "stargz"
defaultRuntimeDefault container runtime, for example "nvidia"

Options ​

spec.options controls how k3sctl performs disruptive operations.

Drain ​

drain controls how nodes are drained during upgrades and reconfiguration.

yaml
spec:
  options:
    drain:
      enabled: true
      timeout: 5m
      gracePeriod: -1
      ignoreDaemonSets: true
      deleteEmptyDirData: true
      disableEviction: false
KeyDescription
enabledDrain nodes before restarting them (default true)
timeoutDrain timeout (default 5m)
gracePeriodGrace period passed to kubectl drain (default -1)
ignoreDaemonSetsIgnore DaemonSet pods when draining (default true)
deleteEmptyDirDataDelete emptyDir data when draining (default true)
disableEvictionForce delete pods instead of evicting them (default false)

Concurrency ​

yaml
spec:
  options:
    concurrency:
      limit: 30
      uploads: 5
KeyDescription
limitMaximum number of hosts to process in parallel (default 30)
uploadsMaximum number of concurrent file uploads (default 5)

Evict taint ​

yaml
spec:
  options:
    evictTaint:
      enabled: false
KeyDescription
enabledTaint nodes before eviction during disruptive operations (default false)

Additional manifests ​

Any other YAML documents in the configuration file are applied to the cluster after installation. Separate them with ---:

yaml
# ... Cluster document ...
---
apiVersion: v1
kind: ConfigMap
metadata:
  name: example
data:
  key: value

Each document must be a valid Kubernetes manifest. k3sctl passes them to kubectl apply on the server node.
